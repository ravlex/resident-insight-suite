# План реализации расширенного функционала ИВЦ ЖКХ и ТЭК

На основе предоставленных документов (анализ проблем и идеи функционала), мы расширяем систему до полноценного управленческого кабинета принципала (УК/РСО).

## 1. Новые функциональные модули

### Взаимодействие с ИВЦ (`/tickets`)
Создание единого пространства для коммуникации между УК и ИВЦ.
- Реестр официальных запросов со статусами (Новый, В работе, Ответ получен, Закрыт).
- Чат по каждому запросу с историей переписки и вложениями.
- Контроль сроков исполнения (SLA).

### События и уведомления (`/notifications`)
Центр управления критическими изменениями.
- Лента уведомлений: финансовые аномалии, новые обращения, сроки задач.
- Настройка пороговых значений (например, уведомлять, если собираемость по дому ниже 80%).

### Внутренние задачи (`/tasks`)
Система контроля исполнительской дисциплины внутри УК.
- Постановка задач сотрудникам на основе аналитики или обращений.
- Канбан-доска или список с дедлайнами и приоритетами.

### Интеллектуальный помощник (AI)
- **AI-Протоколирование:** Автоматическое суммаризация переписки с жителями или ИВЦ (краткое содержание, факты, решения).
- **AI-Аналитик:** Чат-интерфейс для вопросов по данным ("Какие дома имеют наибольший рост долга?", "Сделай сводку за год").

## 2. Обновление существующих разделов

### Дашборд (Главная)
- Добавление виджета "Риски и отклонения" (из раздела События).
- Добавление виджета "Активные задачи".
- Интеграция AI-строки для быстрых запросов по данным.

### Взаимодействие с потребителями (`/communications`)
- Переименование/расширение текущего раздела "Обращения".
- Добавление функционала массовых рассылок (Email/SMS/Push).
- История коммуникаций по каждому лицевому счету.

## Технические детали
- Использование **Lucide React** для новых иконок (Ticket, Bell, CheckSquare, MessageSquareText).
- Компоненты **shadcn/ui**: Tabs, Tooltip, Toast для уведомлений.
- Хранение состояний через React `useState` (имитация бэкенда).
- Адаптивная верстка для всех новых разделов.

---
*Этот план расширяет прототип до полноценной экосистемы управления, решая проблему "отсутствия единого пространства" и "непрозрачности процессов".*
